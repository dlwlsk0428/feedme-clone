# URL to Markdown 변환기

## Decisions

- 본문 추출은 `defuddle`로 합니다. 다른 추출 라이브러리로 바꾸지 않습니다.
- 페이지는 서버에서 가져와 변환합니다. Node에서는 `defuddle/node`와 `linkedom` 조합을 씁니다.
- 프롬프트와 본문을 합친 텍스트가 대략 6,000자 이하면 ChatGPT(`https://chatgpt.com/?q=`)와 Claude(`https://claude.ai/new?q=`)의 쿼리로 넘깁니다. 넘으면 전체를 클립보드에 복사하고 새 대화만 엽니다. 잘라서 보내지 않습니다.
- 프롬프트는 저장하지 않습니다. 프리셋 선택도, 직접 입력 문구도 1회용입니다.
- 변환기 화면(보노보노 PPT 판)의 나쁜 UI/UX는 의도입니다. 버튼 없는 밑줄 단어, 동작마다 다른 클릭 횟수, 거의 없는 피드백, 고정 폭 880px, 포커스 표시 없음을 "고치지" 않습니다. `ui-composition`의 예외는 이 화면에만 적용합니다.

## Boundaries

- 이 화면의 기능은 모두 실제로 동작해야 합니다. 의도적으로 망가뜨리는 것은 단서와 일관성뿐이며, 기능이 막히면 안 됩니다. 밑줄 단어에는 그 동작과 클릭 횟수가 같은 문장에 평문으로 적혀 있어야 합니다.
- 다른 화면에는 이 스타일을 확산하지 않고 `ui-composition`을 따릅니다.
- 변환 이력 저장, 계정, ChatGPT·Claude 외 LLM, 로그인 필요 페이지와 PDF 변환은 범위 밖입니다.
- 요청 제한, URL 허용 목록, 사설망 차단 같은 보안 하드닝도 학습 템플릿 예산 밖이라 하지 않았습니다. 서버가 임의 URL을 가져오는 구조임을 알고 다뤄야 합니다.

## Why

`defuddle`은 사용자 요구 사항입니다. 브라우저는 CORS 때문에 다른 도메인 페이지를 직접 가져올 수 없어서 서버가 HTML을 가져옵니다. 긴 글을 쿼리에 실으면 URL 길이 한도에 걸리고, 잘라 보내면 요약·번역 결과가 불완전해지므로 클립보드로 넘기기로 사용자가 확정했습니다. 나쁜 UI는 강의용 학습 템플릿에서 사용자가 의도해 고른 것입니다.

## Reconsider when

- ChatGPT·Claude의 `q` 쿼리 파라미터가 입력란을 채우지 못하게 바뀌면 넘기는 방식을 다시 봅니다.
