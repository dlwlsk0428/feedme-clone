# 변환기 최악의 UI 대회판 (converter-chaos-ui)

URL 변환기(보노보노 PPT 판)에 "최악의 UI 대회" 같은 킹받는 장치 8가지를 더한다. 기존 화면의 나쁜 UI는 그대로 두고 그 위에 얹는다. 모든 장치는 끝까지 하면 반드시 통과되어, 변환 기능은 한 번도 막히지 않는다.

## Linked sources

- [url-to-markdown-converter](../../decisions/url-to-markdown-converter.md): 이 화면의 나쁜 UI가 의도라는 결정, 기능은 막히면 안 된다는 경계, 천장 3회 규칙. 이 spec의 모든 장치가 따라야 하는 계약이다.
- [ui-composition](../../decisions/ui-composition.md): 일반 UI 원칙. 변환기 화면만 예외이고, 이 spec은 다른 화면을 건드리지 않는다.
- 앱 전제(`PRODUCT.md`)는 없다.

## 사용자에게 달라지는 점

변환 흐름이 "빈칸에 URL, 변환 한 번 클릭"에서 아래 순서로 바뀐다.

1. **변환**을 클릭하면 먼저 **뽑기**가 나온다(룰렛 또는 복불복 쪽지, 실행마다 무작위로 하나).
2. 꽝이면 다시 뽑는다. 연속 3번 꽝이면 4번째는 반드시 당첨이다.
3. 당첨되면 **가짜 로봇 확인**("저는 로봇이 아닙니다" 체크 3번)이 나온다. 누를 때마다 문구가 바뀐다("정말요?" 등).
4. 이어서 **변환 확인창**("정말 변환하시겠습니까?")이 나온다. [예]/[아니오] 위치는 열릴 때마다 바뀌고, 어느 쪽을 눌러도 변환이 진행된다.
5. 변환이 진행되는 동안 **99% 진행률 바**가 99%에서 멈춰 있다가 변환이 끝나면 사라진다.

그 밖에 화면 전반에 아래 장치가 붙는다.

- **도망가는 쿠키 배너**: 화면 진입 시 나타나고 [모두 거부]가 커서를 피해 움직인다. 4번 피하면 멈춰서 눌러진다. [모두 수락]은 처음부터 눌러진다.
- **번식하는 광고 팝업**: 화면 진입 시 1개가 뜬다. 작은 × 를 누르면 사라지고 2개가 새로 뜬다. 3세대째(총 7번 닫기)부터는 닫아도 새로 뜨지 않는다.
- **WordArt·혼합 폰트**: 제목에 무지개 WordArt 효과, 본문 글자 크기가 문단마다 다르다.
- **🐟 커서**: 마우스 커서가 물고기 모양으로 바뀐다(실제 클릭 지점은 화살표 끝이 아닌 어긋난 위치로 느껴져도 된다).
- **이탈 방지 팝업**: URL을 입력했거나 결과가 있는 상태에서 탭을 닫거나 새로고침하려 하면 "저장하지 않은 변경사항이 있습니다"를 보여 준다. 브라우저 기본 확인창이므로 나가는 선택이 항상 있다.

## 범위

- 포함: 위 장치 8가지(뽑기, 가짜 로봇 확인, 변환 확인창, 99% 진행률 바, 쿠키 배너, 광고 팝업, WordArt·혼합 폰트와 🐟 커서, 이탈 방지 팝업), 이 장치들을 설명하는 평문 문구, 바뀐 흐름에 맞춘 기존 안내 문구와 테스트의 수정.
- 기존 동작은 유지: URL → 마크다운 변환, 복사(두 번 클릭), 다운로드(한 번 클릭), ChatGPT·Claude 넘기기, 처음으로 돌아가기, 다크 모드 토글, 광고 모드 전환.

## 수용 기준

1. 변환을 클릭하면 뽑기가 나온다. 뽑기 방식(룰렛, 쪽지)은 실행마다 무작위이고, 두 방식 모두 나올 수 있다.
2. 꽝이면 같은 방식으로 다시 뽑는다. 무작위를 고정해 연속 3번 꽝을 만들면 4번째는 반드시 당첨임을 자동 테스트로 확인할 수 있다.
3. 당첨 후 로봇 확인 체크를 3번 누르면 다음 단계로 넘어간다. 3번 미만이면 넘어가지 않고, 누를 때마다 문구가 바뀐다.
4. 확인창의 [예]/[아니오]는 열릴 때마다 위치가 바뀔 수 있고, 어느 쪽을 눌러도 변환이 시작된다. 변환 결과는 기존과 같다.
5. 변환 중에는 진행률 바가 99%에서 유지되고, 결과가 나오거나 오류가 나면 사라진다. 진행률 바가 변환을 지연시키지 않는다.
6. 쿠키 배너의 [모두 거부]는 커서를 4번 피한 뒤 눌러지고, 누르면 배너가 사라진다. [모두 수락]을 누르면 바로 사라진다.
7. 광고 팝업은 닫을 때마다 2개가 새로 뜨고, 3세대째부터는 새로 뜨지 않는다. 모든 팝업을 닫을 수 있고, 팝업이 떠 있어도 URL 입력과 변환 흐름을 진행할 수 있다(모달이 아니다).
8. 이탈 방지 팝업은 URL이 비어 있고 결과도 없을 때는 나오지 않는다.
9. 위 모든 장치에는 동작과 횟수(예: "체크를 3번", "× 를 7번")가 같은 문단의 평문으로 적혀 있다. 숨겨진 것은 단서의 위치와 일관성뿐이다.
10. 장치를 모두 통과한 뒤 기존 기능(복사, 다운로드, LLM 넘기기, 처음으로 돌아가기)이 이전과 똑같이 동작한다. 처음으로 돌아가기를 누르면 뽑기 연속 꽝 횟수도 초기화된다.
11. 다른 화면에는 이 스타일이 번지지 않는다(`ui-composition` 유지).

## 확정된 제약과 근거

- 기능이 막히면 안 된다. 운이 변환을 영영 막지 못하게 천장 3회를 둔다. 근거: 기존 계약이 "의도적으로 망가뜨리는 것은 단서와 일관성뿐"이라고 정했고, 사용자가 이 방식을 확정했다.
- 뽑기는 변환 여부를 정하는 첫 관문이고, 확인 절차(로봇 확인, 확인창)는 그 뒤에 온다. 사용자가 요청한 순서다.
- 뽑기 결과는 저장하지 않는다. 연속 꽝 횟수는 새로고침하면 초기화된다.

## 가정(덮어쓸 수 있음)

- 뽑기 UI는 룰렛과 쪽지 두 가지로 하고, 칸·쪽지 구성과 당첨 확률은 구현이 정한다. 단 천장을 넘지 않는다.
- 로봇 확인 문구, 팝업 광고 문구, 쿠키 배너 문구는 구현이 정한다.
- 이탈 방지 팝업은 브라우저 기본 확인창을 쓴다.
- 고정 폭 880px 레이아웃과 좁은 화면 대응 없음은 기존 결정을 따른다.

## 범위 밖

- 소리, 영상 재생, 실제 사용자 정보 수집이나 외부 광고 연동. 가짜 장치만 만든다.
- 보안 하드닝, 접근성 개선, 성능 방어. 학습 템플릿 예산 밖이다.
- 변환 이력, 계정, 다른 LLM 지원.

## 남은 위험

- 무작위 장치(뽑기 방식, 확인창 위치, 쿠키 배너 회피)가 늘어나 기존 E2E·단위 테스트가 흔들릴 수 있다. 무작위를 고정할 수 있어야 한다는 수용 기준 2가 이 위험을 막는 장치다.
- 팝업이 많이 떠 있으면 화면이 가려져 변환 흐름이 힘들 수 있다. 의도이지만, 팝업이 모달이 아니라는 기준 7로 막힘은 방지한다.
